## ESP32 iBeacon Arduino Sketch

Save as `ibeacon_hmkf.ino`. Flash one per ESP32, changing only `BEACON_MINOR`.

```cpp
#include <BLEDevice.h>
#include <BLEAdvertising.h>

// ── Configure one of these per device ──────────────────────────
// A = 4, E = 5, C = 6, B = 7
#define BEACON_MINOR 4        // ← change per device: 4=A, 5=E, 6=C, 7=B
// ───────────────────────────────────────────────────────────────

// Must match ArenaConfiguration.prototype in the iOS app
#define BEACON_UUID  "F7826DA6-4FA2-4E98-8024-BC5B71E0893E"
#define BEACON_MAJOR 1

// TX power byte embedded in the iBeacon payload.
// -59 dBm (0xC5) is the standard 1m calibration value.
// Lower TX = shorter range: 0xB0 ≈ -80dBm, 0xC9 ≈ -55dBm
#define MEASURED_POWER 0xC5

void setIBeaconPayload(BLEAdvertising* adv) {
    // Parse UUID string into 16 bytes (big-endian)
    const char* uuidStr = BEACON_UUID;
    uint8_t uuid[16];
    int i = 0, j = 0;
    char hex[3] = {0};
    while (uuidStr[j] && i < 16) {
        if (uuidStr[j] == '-') { j++; continue; }
        hex[0] = uuidStr[j++];
        hex[1] = uuidStr[j++];
        uuid[i++] = (uint8_t)strtol(hex, nullptr, 16);
    }

    uint8_t payload[30] = {0};
    // Flags
    payload[0] = 0x02; payload[1] = 0x01; payload[2] = 0x06;
    // Manufacturer specific data header (Apple, iBeacon)
    payload[3] = 0x1A; payload[4] = 0xFF;
    payload[5] = 0x4C; payload[6] = 0x00; // Apple company ID
    payload[7] = 0x02; payload[8] = 0x15; // iBeacon type + length
    // UUID (16 bytes)
    memcpy(&payload[9], uuid, 16);
    // Major (big-endian)
    payload[25] = (BEACON_MAJOR >> 8) & 0xFF;
    payload[26] =  BEACON_MAJOR       & 0xFF;
    // Minor (big-endian)
    payload[27] = (BEACON_MINOR >> 8) & 0xFF;
    payload[28] =  BEACON_MINOR       & 0xFF;
    // Measured power
    payload[29] = MEASURED_POWER;

    BLEAdvertisementData advData;
    advData.addData(std::string((char*)payload, 30));
    adv->setAdvertisementData(advData);
}

void setup() {
    BLEDevice::init("");
    BLEDevice::setPower(ESP_PWR_LVL_N12);  // -12 dBm — tune this (see below)

    BLEAdvertising* adv = BLEDevice::getAdvertising();
    setIBeaconPayload(adv);
    adv->setMinInterval(160);  // 100ms (160 × 0.625ms)
    adv->setMaxInterval(160);
    adv->start();
}

void loop() {
    delay(10000);
}
```

## TX Power Tuning

Goal: stand 5m from each beacon — Beacon Diagnostic view should show similar RSSI across all 8 (within ±3 dBm). The Kontakt beacons will likely read stronger; reduce `setPower` on the ESP32s to compensate, or dial down TX on the Kontakt app.

| ESP constant | dBm | Use |
|---|---|---|
| `ESP_PWR_LVL_N12` | −12 | Start here — good for 15–20m in open air |
| `ESP_PWR_LVL_N9` | −9 | If ranging drops at far end of 60m arena |
| `ESP_PWR_LVL_N6` | −6 | Match to Kontakt measured RSSI at 5m |

## Why 8 Beacons Matters

With 4 beacons (A, E, C, B) the geometry is poor:
- Corners (K/F/H/M) are the worst-covered zones — up to 28m from the nearest beacon
- At the A end only A and E/B are close enough to trilaterate — effectively 2-anchor at corners
- GDOP is high along the centreline

Adding H, M, K, F:
- Maximum distance to nearest beacon drops from ~28m to ~14m (half)
- Every position now has ≥3 beacons within 15m — minimum for reliable trilateration
- Corner and quarter-marker zones ("KXF", "HXM") go from worst to best coverage
- Centroid weighting becomes more symmetric — less bias toward long-side midpoints

## Practical Notes

- **Power:** USB power banks for the ESP32s
- **Mounting:** Offset 15–30cm from metal walls on wooden posts or PVC pipe to reduce ground-plane effects
- **ESP32 stability:** BLE stack can drop after 30+ min. If a beacon disappears, add a watchdog reset in `loop()` — but try without first
- **Battery note (for Minew i3 when they arrive):** Use Energizer Ultimate Lithium AA cells in cold barns — standard alkaline lose significant capacity below 0°C
